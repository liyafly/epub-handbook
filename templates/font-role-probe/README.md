# 字体角色探针

在真实阅读器里确认：哪些字体真的固定，哪些会被换字覆盖。结果决定 [SPEC §8](../../docs/final/SPEC-实现约束.md) 的字体规则怎么改。

## 构建

字体不进仓库。复制 [fonts.example.json](fonts.example.json)，把路径改成本机字体（相对这个 JSON 文件），放到被忽略的目录：

```sh
uv run --no-project --with fonttools python templates/font-role-probe/build.py --fonts <你的 fonts.json>
```

产物在 `dist/`，SHA 在 `dist/inventory.json`。包里含字体子集，只供本机测试，不要分发。

## 四个包

| 包 | 正文字体 | `ibooks:specified-fonts` | 要回答的问题 |
| --- | --- | --- | --- |
| A | 不写 | 无 | 自由正文时，角色字体还生效吗 |
| B | 不写 | 有 | A 失败时，加这个 meta 能救回来吗；代价是不能换正文字体吗 |
| C | 嵌入字体 | 有 | 锁定正文时，正文和角色都固定吗 |
| D | 系统字体链 | 有 | 系统字体链实际命中什么 |

四个包的书信页带横线，多看里横线不正常，判断字体时不用管。另产书信成品，只有书信字体，没有标记字：`font-role-letter.epub` 给多看以外的阅读器，`font-role-letter-duokan.epub` 给多看，无横线。

## 怎么看

每个角色行开头有一个标记字。标记字只存在于该角色的嵌入字体里：**显示标记字，表示字体生效；显示方块、问号或空白，表示没生效。**

| 编号 | 位置 | 标记字 | 看什么 |
| --- | --- | --- | --- |
| T1 | 角色字体 | 题 | 标题字体 |
| B1 | 角色字体 | 正 | 只有 C 包应显示；A、B、D 显示方块才对 |
| L1、V1、N1 | 角色字体 | 信、诗、注 | 书信、诗歌、注释字体 |
| S1 | 角色字体 | 信 | 只有常规字重时，粗体的样子 |
| 书信页 | 书信版式 | 信 | 对齐方式；横线在短信、跨页和超长段落下是否跟随文字 |
| M1 | 缺字观察 | 信 | 字体缺字时显示成什么 |
| E1–E3 | 英文字体 | R | 系统字体优先的链命中了什么 |
| E4、E5 | 英文字体 | I、P | E4 是真斜体，E5 只是字母倾斜 |
| E6–E8 | 英文字体 | E7 是 M | 系统斜体、代码字体、中文是否被斜切 |

## 实测步骤

1. 阅读器：Apple Books（iPhone、macOS）、Reeden（iPhone、macOS）、Kindle（Send to Kindle）。Readest 可选。
2. 每个包先用默认设置看一遍，记录上表。
3. 把阅读器字体换成别的字体，再看一遍。标记字消失的角色，就是被换字覆盖了。
4. 调大字号、切夜间主题，再看书信页。
5. 记录阅读器版本、包的 SHA、截图和现象，写入 [reader-matrix](../../docs/final/reader-matrix.yaml) 的 `probe-font-role`。

状态：默认设置已看过前几页，换字未记录，见矩阵。标记字是私用区字符，个别阅读器可能特殊处理，所以判断时同时看字形本身。
