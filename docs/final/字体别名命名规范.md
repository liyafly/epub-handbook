# 字体别名命名规范

> 状态：工程契约。适用于此后新建 EPUB、清洗时新增的字体资源、`@font-face`、CSS class、模板和预设。
>
> 不追溯改写已经交付给读者的 EPUB；只有用户明确授权时，才对既有外部书的 CSS 别名做迁移。

## 1. 目标

字体别名描述**排版角色**，不伪装成品牌名、书名或授权字体的正式名称。这样能在换字体、做子集、检查 fallback 时保持稳定，也避免把示例命名误用到生产书。

## 2. 允许的别名

| 用途 | `@font-face` family / 文件名示例 | CSS 绑定示例 |
| --- | --- | --- |
| 西文 | `en` / `en.ttf` | `.font-en` |
| 正文宋体 | `st` / `st.ttf` | `.font-st` |
| 楷体 | `kt` / `kt.ttf` | `.font-kt` |
| 仿宋 | `fs` / `fs.ttf` | `.font-fs` |
| 黑体 | `ht` / `ht.ttf` | `.font-ht` |
| 特殊标题 | `tszt-title` / `tszt-title.ttf` | `.title-tszt` |
| 特殊签名 | `tszt-sign` / `tszt-sign.ttf` | `.signature-tszt` |
| 生僻字补字 | `tszt-rare` / `tszt-rare.ttf` | `.rare` |
| 覆盖正文全部实际用字的宋体 | `st-all` / `st-all.ttf` | `body`（直接锁定；既有 `.body-font-locked` 仅兼容保留） |

`tszt` 是“特殊字体”的角色缩写；有多个补字资源时追加稳定序号，例如 `tszt-1`、`tszt-2`。文件名、OPF `id` 和 `font-family` 可以不同，但应共享同一个角色词根，方便追踪。

## 3. 禁止的命名

新建或修改活跃模板时，不得引入以下模式：

- `BookSong*`、`BookKai*`、`BookHei*`、`BookTitle*`、`BookSignature*`、`BookBody*`；
- `RareSong*`；
- `.book-song`、`.book-kai`、`.book-hei`、`.book-*` 等把“book”当作字体角色的 class；
- 用授权字体正式名称作为项目通用 alias，或为同一角色重复堆叠不同平台别名。

这条规则不禁止 OPF 元数据中的真实书名，也不要求重命名已有外部 EPUB 内的历史 alias。

## 4. 清洗和制作规则

1. 保留输入 EPUB 原有别名，除非用户明确要求迁移；不要为统一命名而改动现有书。
2. 新增 `@font-face` 时，先选角色别名，再添加对应 ZIP 资源和 OPF manifest item。
3. 字体链按角色组装：`en` 处理西文，`st` 处理正文，`tszt-*` 只承担确认过的补字或设计角色；稳定结构角色可直接绑定，混合角色使用类，不把多个特殊字体塞入默认正文链。
4. 新模板、starter、style preset、skill 和对外示例只使用本页别名；历史计划、实验快照不做机械回写。
5. 字体授权、文件内部 family/PostScript 名和 CSS alias 是三件事：alias 简短不构成授权证明，嵌入前仍须核对许可。
6. 新增字体资源使用小写扩展名（如 `.ttf` / `.otf`）；ZIP 路径、CSS `url()` 与 OPF `href` 必须大小写逐字一致。只把扩展名改成小写不会改变字体格式。
7. 子集化后优先保持角色 alias、包内路径、CSS URL 和 OPF id 稳定，只替换字体文件字节；随后重新运行字体覆盖、preflight 与 EPUB lint。不得用改名掩盖缺字或失败的子集文件。

## 5. 迁移检查

对活跃文档、模板、skills 和测试执行：

```sh
rg -n \
  'Book(Song|Kai|Hei|FangSong|Title|Signature|Body)|RareSong|book-(song|kai|hei|fangsong|body|heading|kaiti|mono|latin)' \
  docs skills templates scripts
```

命令无结果才允许声称活跃入口已迁移。对真实外部书，另行确认 CSS alias 与 XHTML class 的引用闭环，不以全局替换替代书级审计。
