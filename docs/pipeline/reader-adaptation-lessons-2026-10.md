# 2026 年 10 月阅读器适配复盘（匿名案例）

本文从插图型英文书和技术图文场景提炼可复用的排查方法，重点覆盖 Reeden、Readest 与 Kindle Previewer。书名、作者、原文、真实字体名称、书内资源名、章节页码、内容 ID、私人路径、成品指纹、精确案例数量和本地恢复标识均不收录。具体证据继续保存在本地书级材料；代码中的字体名称、文件名和角色名均为脱敏占位。

本文不新增通用兼容结论。硬约束仍以 [SPEC](../final/SPEC-实现约束.md) 为准，兼容状态以 [reader matrix](../final/reader-matrix.yaml) 的精确 fixture 为准。历史单书观察不能替代当前版本、当前产物的实测。

## 1. 先认清正在检查哪一个包

文件名、版本号和书库封面相同，不能证明正在读同一内容。旧记录即使写着“正式”，也要先核对其产物身份和阶段。

在本地记录候选、测试副本、实际导入载荷的指纹与对应关系，再关联阅读器版本、字号、字体覆盖、主题、窗口和栏数。向主仓回填时只保留判断方法；具体身份、截图、路径和收据留在本地。不要把私有证据索引提交成公开 JSON，也不要用截短哈希替代脱敏。

## 2. Reeden：英文正文为什么全变成斜体，后来怎样改对

### 现象与证据边界

一个案例中，普通叙述大面积显示斜体，源结构只对少量语义强调使用 `<em>`。本地字体映射提示应检查字体族和字面绑定；历史错误截图没有完整输入身份，不能用来作当前成品的严格配对回归。

CSS diff 和维护源确认：原样式用同一个族名声明正体与斜体；修复将斜体拆为独立别名，并显式绑定 `<em>`。这支持“该导入/渲染路径存在样式误匹配”的排查判断，没有证明所有 Reeden 版本的内部实现或覆盖顺序。

### 修法示意

以下为脱敏示例，字体文件和族名均非原书名称。原写法的关键部分：

```css
@font-face {
  font-family: 'body-serif';
  src: url('../Fonts/Serif-Regular.otf') format('opentype');
  font-weight: normal; font-style: normal;
}
@font-face {
  font-family: 'body-serif';
  src: url('../Fonts/Serif-Italic.otf') format('opentype');
  font-weight: normal; font-style: italic;
}
em { font-style: italic; }
```

局部修改斜体声明和强调规则，保留原来的正体声明：

```css
@font-face {
  font-family: 'en-italic';
  src: url('../Fonts/Serif-Italic.otf') format('opentype');
  font-weight: normal; font-style: italic;
}
body {
  font-family: 'body-serif', Georgia, serif;
}
em {
  font-family: 'en-italic', 'body-serif', Georgia, serif;
  font-style: italic;
}
```

修复保留 `<em>` 语义和字体二进制，让普通正文与强调分别请求明确的字体角色。本地修后截图与实际载荷的对应关系支持指定配置下普通文字直立、强调仍为斜体；不扩展为夜间、大字号或全书通过。

标准阅读器可以支持同族多个 face，不应无条件拆分所有书的字体族。遇到类似问题，先检查实际载荷、阅读器字体覆盖、正文继承链、`@font-face` 的族名/字重/样式，再检查字体文件。确认误匹配后才试独立别名；回归同时看普通文字与真正的强调，不能用全局 `font-style:normal` 掩盖语义损失。`epub.typography.english.optimize` 只处理语言声明，不能修字体匹配。

## 3. Reeden：出血、全屏和弹注要分别验

| 项目 | 可复用的经验 | 边界 |
| --- | --- | --- |
| 左右出血 | 只加 `reeden-bleed:leftright` 可能仍未贴边；还需检查容器水平 margin，并给内部图片 `width:100%; height:auto` | 指定样例与配置有效，不自动合入通用版 |
| 全屏插图 | 属性位于 OPF `spine/itemref`，对应 XHTML 应以单张主图为主；不能直接标记含整章正文的 spine 项 | 官方结构说明不等于单书实测 |
| 长转录弹注 | 打开、滚到末尾、关闭、返回触发位置分别记录 | 能滚到底不证明回跳成功 |
| 常规封面与 slim | 桌面显示主图，不能证明手机/多看已自动选中备选图 | 资源存在与选择成功分开验证 |

制作机制参考 [Reeden 出血说明](https://docs.reeden.app/ebook_spec_bleed) 和 [全屏插图说明](https://docs.reeden.app/ebook_spec_fullscreen)。文档会更新，描述的能力不替代本机实测。通用样式保留标准回退，专用增强先做独立候选，确认收益和回退后再采用。

## 4. Readest：先排除旧内容，再判断 CSS 是否有效

### 改 identifier 还不一定隔离成功

本地复查曾发现正式包、测试副本与候选的 partial-MD5 相同，原生 URL 仍指向旧条目。旧截图因此降为受限历史证据；重新隔离并复现原问题后，才继续比较修法。

Readest 的 [摘要函数与导入路径](../../references/readest-import-identity.md) 表明，文件摘要和元数据均参与书库匹配。partial-MD5 只抽样部分字节；OPF 若在 ZIP 后部，改 identifier 可能没有触及抽样范围。不能由“SHA 不同”“新 UUID”或“导入成功”独自推断新内容已经打开。

有效隔离试验只改测试 identifier 与 ZIP 成员顺序，将 OPF 提前，同时保持 `mimetype` 首项且 STORED；再证明其余解压成员不变、摘要不同，最后核对实际条目/载荷和能区分版本的内容。这仍需逐副本确认，不是跨版本缓存保证。不清空用户书库或批量删除缓存。

现有 `epub.metadata.edit` 示例只完成 identifier 修改，不负责摘要碰撞检测、ZIP 重排或原生条目核对。这个能力缺口不能靠把一次性私有脚本复制进 skills 来填补。

### 页底图形裁切：`break-inside:avoid` 不是验收

在排除旧导入包后，一些源图完整的线稿仍会在页底缺笔画；换字号可能使目标图完整，却让相邻图开始裁切。静态检查通过不能消除分页问题。

失败试验提供了反例：仅增加分页声明、改表格图盒或加原子 wrapper，没有可靠解决全部受影响位置。只查原截图、只查一个章节，会漏掉共享机制影响的其他实例。

一个受检案例最终没有重采样图片，而是在限定章节加载的独立 CSS 中增加少量 figure 底部空间。以下保留技术参数作为候选示意，不能自动套给其他书：

```css
body.theme-light figure,
body.theme-dark figure {
  padding-bottom: 0.5em;
}
```

候选仅新增样式及必要引用，图片、字体、旧 CSS 和正文保持。本地连续检查受影响章节、邻图、相邻字号及后续内容，支持所见图主体完整；复杂公式和真值表仍有独立警告。

这是单书分页绕过，不是渲染算法根因证明。阅读器 theme class 不是稳定的跨阅读器 API；规则包含 dark 分支也不等于已经完成夜间验收。

### 书首空白与主题刷新

- 封面/扉页后多空栏时，同时检查前页的 after 与首章的 before。一个案例中，只取消扉页页后分页仍失败，局部取消首章强制起始分页后改善；其他章继续保留章首分页。空白不等于多了一个空 XHTML。
- 夜间纸底曾在已加载章节中没有即时生效，重开本书后改善。不能独立区分 CSS 方案与重开各自贡献时，仍记 warn；复查换章、切主题与重开后的表现。
- 外置 CSS 属于应用设置。“自定义内容 CSS”才作用于书内；内置样例应在外置 CSS 为空时验收，才能证明效果随 EPUB 生效。

## 5. Kindle：复杂图文与封面

| 场景 | 可复用的判断 | 验收边界 |
| --- | --- | --- |
| 图像尺寸 | 对照参考版角色与比例；小图、肖像、全页图不能统一设宽 | 资源数、显示实例数、图像索引数和总览屏数分开记录；总览不等于逐图全尺寸验收 |
| 页底与细线 | 源图完整后查分页；总览找位置，关键图放大看底部笔画与线路端点 | 图主体、细标签及扫码功能分别验收 |
| MathML 与真值表 | 检查长公式右端、编号、表头/rowspan 分组及大字号 | 图片修复不能消除公式溢出或表格分页警告 |
| ASCII 与代码 | 区分代码、说明和对齐表格；不要把自然语言与代码混进一个 pre，或全书缩小字体 | 物理文本块拆并涉及授权差异时，text 红线仍如实报告 |
| 字体覆盖 | 子集未引入回归，不代表母版覆盖全书；特殊字和组合符号另查字体链 | 少量显示正确不等于全书覆盖通过 |
| 重复封面 | 核对 raster cover、cover-image/legacy cover、guide、spine 与封面页实际主图引用 | 局部修复后须重新转换和定点实测，不能删正文或原画规避 |
| 封面比例 | 保留原画，用补边候选比较显示区占宽 | 桌面、手机、实体 Kindle 与其他阅读器分别验；备选图存在不证明自动选择 |

转换产物还要反查真实输入。本地 KPF 内嵌 EPUB 与受检候选的等价证明支持输入绑定；CRC、日志有无错误行另行报告。包内没有的汇总统计，不能从旧产物或空日志补写。

## 6. 插画、环绕与正文保护

- **固定版提供关系，重排版适应屏幕。** 核对跨页构图、插图与完整句的先后、图题/转录入口，不逐页照搬固定坐标。插图移到句末可能改变物理文本块，须单列授权差异和连续正文证明。
- **先保证矩形环绕可读。** figure 控制实例宽度，内图等比铺满；轮廓环绕作为独立试验。历史 CSS 留着 polygon 不代表最终生效，先检查覆盖后的实际规则。
- **宽度按图片角色调。** 窄栏手写图可用转录/预览补充，不能为放大文字裁掉原画。导语、图题及 fullpage 分页约束局部检查。
- **小样收敛后检查全部受影响实例。** 为重复出现的放大、留白和分页问题建立完整清单；改图像尺寸或公式高度后，连同同章表格及说明回归。参见 [匿名验收清单](../../EPUB排版问题复盘与验收清单.md)，不把其未完成项改写成已解决。
- **去纸底不等于删除白色。** 从外部纸区和可复查局部 mask 开始，保护封闭白区、细缝和线稿边缘；浅色、彩色和深色主题分别看。透明后的夜间可读性另验，不全书自动反色。
- **图与入口同页不等于弹注交互完整。** 图/入口分页、长注滚动和回跳分别记录；工具崩溃或锁屏中断记待验。

## 7. 仓库改进与后续优先级

本次围绕现有 skills、starter/demo 构建和字体 provider 边界检查，未对全部实现作完整代码审计；书稿与阅读器设置没有修改。

| 落点 | 已处理的改进 | 边界 |
| --- | --- | --- |
| `epub-reader-verify` | 实际载荷/条目、摘要碰撞、连续分页、完整弹注动作、全部受影响实例和设置恢复 | 不新增 reader pass |
| `epub-special-layout`、英文指南 | 同族误匹配与独立斜体角色的条件性排查 | 保留语义强调和 fallback |
| `epub-audit` | 区分源图损伤与分页裁切、覆盖缺字与字体选错 | 只读扫描不自动批量改图/改字体 |
| `epub-package-ops` | 多比例/slim 保留与重复封面引用核对 | 单封面候选不等于多比例交付 |
| demo README | 说明 identifier 修改不能单独证明导入隔离 | 不删除用户书库绕过 |
| starter `build.sh` | 失败保留本次输入/候选和报告快照；成功清本次临时树；SHA 预检失败保留旧报告 | 不自动清理失败现场；既有书升级前审查定制逻辑 |

后续优先考虑：公开 CLI 的测试副本准备能力、使用自造素材的独立 fixture，以及公式/表格/字体覆盖缺口的持续验收。新能力按 Go SPEC 定契约、golden 和红线；单书绕过不直接写进全局 preset。
